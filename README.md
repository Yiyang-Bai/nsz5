# nsz5

Lossless compression for Oxford Nanopore POD5 files. Decompression
rebuilds the original file byte for byte (same SHA-256), so basecalling
is unchanged by the archive format. `.nsz5` is an archive: decompress
back to POD5 before analysis.

The signal goes through a codec built for nanopore current: fixed-order
linear prediction, magnitude classes, and an adaptive range coder. Arrow
metadata outside the signal is kept as-is. If a signal blob cannot be
regenerated byte for byte with the available zstd builds, that blob is
stored verbatim. The file can only grow; it cannot come back wrong.

## Try the bundled samples

The repository includes four small POD5 files, one excerpt from each
public dataset, so you can check the install and the commands. Each file
has only a few reads to a few dozen reads. Do not quote their ratios.
Full-dataset numbers are at the end of this file.

Requirements: GCC with OpenMP, and Python 3.10+.

```bash
git clone https://github.com/Yiyang-Bai/nsz5.git
cd nsz5
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
make lib
bash examples/quickstart.sh
```

Compression and decompression need `pod5`, `pyarrow`, `numpy`, and
`zstandard` from `requirements.txt`. `blue-crab` is only for converting
BLOW5 to POD5. `pyflac` is only for the FLAC comparison.

`examples/quickstart.sh` compresses, decompresses, and checks all four
samples. Output goes to `examples/out/`, which is gitignored. Each sample
should print `IDENTICAL`.

One file by hand:

```bash
python python/nsz5.py compress \
    examples/samples/rna004_control.pod5 \
    examples/out/rna004_control.nsz5

python python/nsz5.py decompress \
    examples/out/rna004_control.nsz5 \
    examples/out/rna004_control.rebuilt.pod5

python python/nsz5.py verify \
    examples/samples/rna004_control.pod5 \
    examples/out/rna004_control.rebuilt.pod5
```

`verify` compares SHA-256. Matching files print `IDENTICAL`. Files that
differ print `DIFFERENT`.

## Commands

The program is `python/nsz5.py`. It has four subcommands:

```text
python python/nsz5.py compress   in.pod5   out.nsz5
python python/nsz5.py decompress in.nsz5   rebuilt.pod5
python python/nsz5.py verify     a.pod5    b.pod5
python python/nsz5.py bench      in.pod5
```

The default prior is `auto`. If the sequencing kit name contains `rna`,
the codec uses `models/prior.bin` (R9 direct RNA and RNA004). Otherwise
it uses `models/prior_r10.bin` (R10.4.1 DNA). Pass a path, or `none`:

```bash
python python/nsz5.py compress in.pod5 out.nsz5 --prior models/prior.bin
python python/nsz5.py compress in.pod5 out.nsz5 --prior none
```

`--threads` is the number of worker processes. `0` picks the machine's
core count, capped at 32. The default is 1. Both compress and decompress
accept it. Chunks are independent, so a parallel run matches a serial
run byte for byte.

```bash
python python/nsz5.py compress   in.pod5 out.nsz5 --threads 8
python python/nsz5.py decompress out.nsz5 rebuilt.pod5 --threads 8
```

`bench` compares the signal payload with the VBZ payload already in the
POD5. It does not write an archive:

```bash
python python/nsz5.py bench examples/samples/hct116_directrna_r9.pod5
```

A large file is read fully into memory. Compression needs about twice
the POD5 size in RAM.

## What happens to one file

The POD5 is treated as a byte stream. Arrow metadata goes into a
zstd-compressed skeleton. Each VBZ signal blob is decoded to int16 and
compressed again with nsz. On decompression, each VBZ blob is spliced
back at its original offset, and the SHA-256 stored in the header is
checked.

For one int16 chunk, the signal codec is:

```text
int16 signal
  -> order-8 linear prediction (Q14 integers; fitted coefficients for R9/RNA, first difference for R10 DNA)
  -> adaptive bias correction
  -> zigzag the residual, then split it into a magnitude class and a mantissa
  -> pick one of 256 contexts from volatility and surprise
  -> adaptive binary range coding, seeded from a pretrained prior
```

Both priors live in `models/`, about 21 KB each, and each is tied to a
predictor profile. The chunk header records which version was used. A
mismatch is a decode error.

If a chunk does not shrink below the raw int16, it is stored verbatim.
Uniform random input costs at most 28 bytes of header.

## Results on full data

Savings below are against VBZ on the same data. The bundled samples are
too short. Do not substitute their `bench` output for these tables.

Signal level, 20 million samples per chemistry:

| Codec | R9 direct RNA | RNA004 | R10.4.1 DNA | Encode speed |
|---|---|---|---|---|
| nsz5 | 6.432 bits/sample (4.0% below VBZ) | 6.570 (5.9% below) | 6.729 (2.8% below) | about 11–12 M samples/s |
| FLAC -8 | 6.514 (2.8% below) | 6.643 (4.9% below) | 6.855 (1.0% below) | 5–26 M samples/s |
| VBZ (POD5 default) | 6.702 | 6.983 | 6.923 | about 500 M samples/s |
| Uncompressed int16 | 16 | 16 | 16 | — |

Whole-file round trips. The rebuilt POD5 has the same SHA-256 as the original:

| File | Chemistry | Size | Smaller than the original POD5 | Verbatim fallback blobs |
|---|---|---|---|---|
| SG-NEx Hct116 direct RNA | R9.4.1 / SQK-RNA001 | 92 MB | 4.22% | 0 / 7897 |
| ONT RNA004 control subset | RNA004 | 364 MB | 7.79% | 0 / 60053 |
| One GIAB HG002 POD5 | R10.4.1 DNA, 5 kHz | 1.88 GB | 2.83% | 49 / 26300 |

On the same chr22 subset as the ex-zd paper (32.3 billion samples,
slow5tools 1.3.0, sizes from `du`, relative to uncompressed BLOW5):

| Method | Bytes | Relative to uncompressed BLOW5 |
|---|---|---|
| nsz5 | 27,339,081,585 | 2.366 |
| ex-zd zstd | 27,503,933,718 | 2.352 |
| POD5 / VBZ | 28,154,437,312 | 2.298 |
| Uncompressed BLOW5 | 64,685,036,199 | 1.000 |

On 32 threads, compressing this chr22 file drops from 5071 s to 442 s,
and decompressing drops from 2648 s to 393 s. The SHA-256 still matches.

## Layout

```text
src/                 C99 codec (nsz.c, predictor, range coder, contexts)
python/nsz5.py       POD5 archive commands: compress / decompress / verify / bench
python/libnsz.py     ctypes bindings for work/libnsz.so
models/prior.bin     prior for R9 direct RNA and RNA004
models/prior_r10.bin prior for R10.4.1 DNA
examples/samples/    the four small POD5 files above
examples/quickstart.sh
tools/extract_signal.py   dump POD5 signal as little-endian int16 for analysis
tools/slice_pod5.py       write the first N reads of a POD5; this is how the samples were cut
analysis/benchmark.py     signal-level bits/sample against FLAC, zstd, xz, and bzip2
tests/               make test, with AddressSanitizer and UndefinedBehaviorSanitizer
```

To compress a raw signal without the POD5 container, link `work/libnsz.so`.
The API is in `src/nsz.h`.

## Tests

```bash
make test
```

The suite covers zigzag, predictor sync, the range coder, magnitude
splitting, contexts, round trips on real signal, corrupt input that must
not decode as silent wrong data, and refusal to decode when the prior
version does not match.

## Limits

- The codec is about ten-plus million samples per second on one thread, slower than VBZ. Chunks are independent, so `--threads` spreads them across cores.
- After a first difference, R10 DNA is close to white noise, so the gain over VBZ is smaller than on RNA.
- Decompress an archive before handing it to Dorado or any other tool that reads POD5.
- The outer zstd frame of a signal blob depends on the libzstd that wrote the file. If `work/zstd_env_<version>/lib/libzstd.so.1` is present for 1.5.6, 1.5.5, 1.5.2, 1.5.0, or 1.4.9, compression tries those builds. A blob that matches none of them is stored verbatim, and decompression is still byte-identical.
